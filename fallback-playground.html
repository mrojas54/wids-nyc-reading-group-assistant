Model

How to read the model choices

An embedding model turns a paper's title+abstract into a fixed-length vector. Similar papers land near each other in vector space, so cosine similarity ≈ topical similarity.

SPECTER2 (Allen AI) is trained specifically on scientific paper citation pairs — its embeddings line up with Semantic Scholar's, which is why our pgvector cache can mix API-fetched and locally-computed vectors.

Other models (MiniLM, BGE, E5) are general-purpose. They're smaller and faster but live in a different vector space. Switching means S2's pre-computed embeddings become useless and you have to re-embed everything locally.

Sequence length = how many tokens (~words) the model reads before it truncates. SPECTER2 maxes at 512; cutting to 256 saves ~65% compute but lops off long abstracts.

Quantization

FP32 vs FP16 vs INT8 — what's actually changing

Each model weight is normally a 32-bit float. Quantization stores them in fewer bits.

FP32 4 bytes, full precision, baseline.

FP16 2 bytes, ~3 decimal digits. Nearly lossless for inference. ½ the file size.

INT8 1 byte, only 256 distinct values per weight. Each tensor gets one shared scale factor: w' = round(w / scale) · scale. ¼ the file size, ~2× faster matmuls — at the cost of measurable accuracy drift.

Per-tensor: one scale per weight matrix (faster, more drift). Per-channel: one scale per output row (slightly bigger, tighter parity). Static: also quantizes activations using a calibration dataset; smallest + fastest, but needs ~100 representative inputs to set activation scales.

Parity thresholds

Why two thresholds, not one?

For each of the 11 fixture papers, we compare the local INT8-ONNX vector to S2's canonical FP32 vector with cosine similarity (1.0 = identical direction).

The original spec used a single threshold (cos ≥ 0.997). That turned out to be aspirational — INT8 doesn't preserve a 110M-param transformer that tightly. Most papers land at 0.99+, but specific outliers drift to 0.94–0.95 (long abstracts with rare vocabulary push activations outside the dynamic quantizer's calibration range).

The two-threshold contract (median ≥ 0.99 + min ≥ 0.93) tolerates expected outliers while still catching a genuinely broken export. See commit 17589da.

Vercel budget

Cold start vs timeout

Cold start = the one-time cost on the first request a Fluid Compute instance handles: fetch the ONNX blob from Vercel Blob (~80 MB/s), load it into the WASM runtime, init the tokenizer. Subsequent requests on the same instance skip this (warm).

Timeout = the hard cap per request. Default 300s on Vercel; we set 60s for /admin/suggest. If WASM inference plus cold start exceeds this, the function 504s — which is why AbortSignal cancellation between token chunks matters (6116441).

Bigger model → bigger blob → longer fetch → longer cold start. That's the main trade-off when you flirt with FP16 or larger architectures.

What this playground is

The WiDS reading-group assistant has a 3-tier embedding pipeline for paper similarity. When Semantic Scholar (S2) is rate-limited or down, the suggest endpoint falls back to running SPECTER2 locally — as ONNX-quantized weights in a WASM runtime inside a Vercel Function.

Tier 1
Semantic Scholar API — canonical embeddings, but rate-limited (429s) and occasionally down.
Tier 2
pgvector cache (paper_embeddings) — warm hits for previously-seen papers.
Tier 3
WASM / ONNX fallback — local INT8-quantized SPECTER2 inference. Configured by everything in this playground.
